# Scheduled run prompt

This prompt is a template, not evidence that a schedule exists. On a scheduled invocation you are a top-level session: follow AGENTS.md, autonomy/README.md, PROCESS.md and RECOVERY.md. Inspect Git, the GitHub Issues queue and `autonomy/autonomyctl.py status` before acting. Never fall back to the archived local registry. Use a unique owner for this run. Pick a ready issue that is not claimed; if its claim fails, it is busy: pick another ready issue, and never take over solely because a claim expired. Claim before writes and delegation, then work in that task's worktree under the user's existing scope, delegate one level deep when authorized, claim resources only while mutating them, collect evidence and independent review, integrate under `integration:master`, update the queue, stop delegates and clear runs. Work that must continue beyond this run is a separate top-level task session, never a delegate holding your lease. Do not ask or wait for user input in a noninteractive run: record missing information as blocked and report it. Avoid idle churn. Before ending, run `python3 autonomy/automation_pause.py --finalize --owner OWNER [--task issue-N]`, then `autonomyctl.py finish` regardless of its result. Follow PROCESS for error handling and metadata; never operate another project's automation. Do not resume a paused schedule without explicit owner instruction.
