# Process

The coordinator converts each actionable request into a GitHub issue in `Tarolrr/screeps` with acceptance criteria, priority and dependencies before delegation. Coordinate non-overlapping worker scopes. Prefer native subagents and, where available, the lightweight `gpt-6.1-terra` model; use Happier-managed workers only on explicit user request. System, developer and user instructions govern whether delegation is allowed. A read-only reviewer independently assesses the result and evidence; report when that is unavailable. The coordinator alone edits issues, labels and comments and owns the queue and acceptance decision. See GITHUB_ISSUES for the status and dependency model; the local task file is a read-only migration archive and never a fallback. Users' instructions and already granted scope continue to apply; no blanket publication, external messaging, server mutation, spending, or scheduler activation is inferred from this kit.

On task completion — evidence collected, review verdict recorded, issue closed — the coordinator commits the task's scope as a separate commit referencing the issue and pushes to the default branch. Run artifacts under `*/.runs/` are local disposable evidence and are not committed; verdicts and run ids live in docs and issue comments. Files touched by several tasks land in the latest touching task's commit, noted in the commit message. Intermediate commits during a task are optional; completion is the commit point.

A run may produce useful work, be idle (no ready work and no new facts), busy (another coordinator holds the lease), or blocked (a necessary action or information is unavailable). Idle starts with read-only inspection and makes no tracked changes, commits, pushes, builds or redundant verification delegates. Busy stops without taking or removing the other lease. Do not invent new facts to justify a cycle.

For noninteractive scheduled runs, do not wait for answers. If required information is missing, record `blocked` with `blocked_reason: needs_clarification`, `missing_information`, and the next action for a manual coordinator. Dependencies of blocked tasks are not ready. Complete and stop workers, clear runs, and release your lease. Report errors without exposing credentials.

If a run is known to be scheduled, that origin persists throughout the run. When the queue has no ready or active work, pause only the configured project automation during that same run, even if useful work was completed. Scheduled release checks the queue and performs the pause under the lease. If origin is known from delivery but environment metadata is missing, explicitly invoke `automation_pause.py --owner OWNER --automation-id ID` before release. Never infer a manual run from missing metadata. Queue errors are not idle. Pause failure is reported; release still occurs, and a durable per-lease receipt prevents repeated POSTs. No automatic resume: owner activation is explicit. A manual run never pauses the schedule merely because the queue is empty.
