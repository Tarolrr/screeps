# Scheduler bootstrap

No schedule is configured or active through this kit. GitHub Issues is the sole active queue; the migrated local registry is a read-only archive and not a fallback. Creating or enabling one requires a separate explicit owner instruction. After authorization, the owner must select and configure the actual project scheduler, confirm its identity and delivery of `AUTOMATION_PROMPT.md`, and arrange `SCREEPS_AUTOMATION_ORIGIN=scheduled` and `SCREEPS_AUTOMATION_ID=<project automation ID>` for each invocation. Do not reuse another project's identity or credentials.

The optional Happier self-pause adapter reads `~/.config/screeps-strategy/automation.json` outside the checkout. It defaults to disabled when missing or invalid. Only after explicit activation, create a private file with `enabled: true`, `automation_id`, `server_id`, and `server_url`; the latter must be a local HTTP(S) server URL. The ID must be alphanumeric; the server ID permits letters, digits, dot, underscore and hyphen. The helper reads credentials from that configured server's Happier access file without printing them, refuses redirects, sends a single pause POST and checks GET readback. Configure the scheduler's metadata to match the same project ID. A mismatched or missing identity fails closed. Do not place secrets in the repository.

Verify configuration without network using `python3 autonomy/automation_pause.py --check`. This checks local configuration and credentials, not scheduling or pause behavior. Before enabling, review PROCESS and RECOVERY and test only against an isolated mock service. `release` performs scheduled finalization when both metadata values identify the configured automation. It releases the lease even when finalization fails and reports `automation_finalize`. Review the error and do not retry an uncertain pause blindly; the receipt prevents a duplicate attempt for that lease.
