# Ограничения runtime и наблюдаемости Screeps

Для архитектуры #17; исследование, не доказательство работы реализации. Основание: официальные [game loop](https://docs.screeps.com/game-loop.html), [CPU](https://docs.screeps.com/cpu-limit.html), [API](https://docs.screeps.com/api/) и [modules](https://docs.screeps.com/modules.html); дополнительно прочитан локальный standalone `@screeps/engine` 4.3.0 и `@screeps/driver` 5.3.0. Поведение конкретного driver и модов не следует автоматически переносить на официальный сервер.

## Тик, состояние и сбои

- В начале тика `Game` представляет наблюдаемое состояние; действия планируются и разрешаются после выполнения кода, а изменения мира видны в следующем тике. `OK` означает принятие намерения, не доказательство эффекта. Например, после `move` атака в том же тике проверяется из старой позиции. Конфликты разрешает движок, а не порядок произвольных вызовов; учитывать [приоритеты действий](https://docs.screeps.com/simultaneous-actions.html), общие ресурсы и действия других игроков.
- На тик строить неизменяемый снимок собственных данных: значения, id, время, видимость и возраст. Не сохранять ссылки на `Game`-объекты как актуальное состояние следующего тика; заново получать по id и проверять отсутствие/потерю видимости. Heap/global и кэш — расходуемая оптимизация, восстанавливаемая из Memory и текущих наблюдений; reset может произойти при обновлении кода, остановке runtime и других причинах. Документация game loop содержит исторически упрощённую фразу о сбросе globals каждый тик; [официальная статья о кэшировании](https://docs.screeps.com/contributed/caching-overview.html) описывает сохранение между тиками до reset. Корректность не зависит от того, сколько тиков heap проживёт.
- `Memory` сериализуется как JSON; сохранять версии схемы, простые значения и устойчивые идентификаторы, а не прототипы или циклические ссылки. В локальном driver `runtime/runtime.js` обычный `game.run` обёрнут в `try/catch`, затем сериализуется `_parsed` и возвращаются intents: необработанное JS-исключение само по себе не откатывает предшествующие изменения. Но сбой сериализации, жесткий timeout/isolate halt или другая ошибка вне этого пути могут не вернуть результат: `runtime/make.js` сохраняет intents лишь после успешного возврата sandbox. Гарантия для всех вариантов CPU termination и серверов **не установлена**; нельзя считать ни autosave, ни откат универсальными. См. [driver runtime](https://github.com/screeps/driver/blob/master/lib/runtime/runtime.js), [make](https://github.com/screeps/driver/blob/master/lib/runtime/make.js).
- CPU ограничен `Game.cpu.tickLimit`; завершение может прервать любой шаг. Критические защитные и восстановительные действия исполняются раньше необязательных расчётов, с запасом CPU; это не обещает успех при исчерпанном лимите.

## Учёт действий и восстановление

Нет установленной ACID-транзакции между Memory и миром, гарантии exactly-once или атомарного общего коммита intents. Запись в Memory перед вызовом API — логическое предварительное намерение, **не доказанный синхронный durable write-ahead log**. Для важных операций хранить стабильный operation ID, контекст, целевые id/имя, количество, тик и состояние; отделять запланированное, выданное, подтверждённое и неопределённое. Повторный запуск сначала сверяет наблюдения, затем повторяет действие только при доказанной безопасности; истечение времени или `OK` не превращают неопределённость в подтверждение. Идемпотентность — свойство конкретной операции и её ключа, не общее свойство API.

Например, уникальное имя spawn помогает обнаружить уже существующего или создаваемого creep, но после его смерти не доказывает, что spawn никогда не был выполнен. Общее изменение энергии не доказывает отдельную доставку, если одновременно идут другие операции. При потере видимости, пропущенных тиках, конфликтующих операциях или исчезнувшей цели сохранять UNKNOWN и ограничивать риск повторного расхода. Это ограниченное best effort восстановление; как долго хранится неопределённость и что разрешено делать при ней — контракт конкретной операции. Не смешивать предполагаемые и подтверждённые деньги в ledger.

## События и атрибуция энергии

`Room.getEventLog` описывает события предыдущего тика в видимой комнате ([API](https://docs.screeps.com/api/#Room.getEventLog)); при потере видимости или пропуске тиков это не долговременный журнал. В локальном engine `creeps/transfer.js` и `withdraw.js` записывают `EVENT_TRANSFER` с источником `objectId`, `targetId`, типом и фактическим amount; withdraw меняет направление относительно вызывающего creep. Событие помогает подтвердить доставку, но не содержит operation ID стратегии и само не доказывает уникальную связь при нескольких кандидатах.

Локальный `creeps/build.js` записывает `EVENT_BUILD.data.amount` как прирост прогресса (`boostedEffect`), а списывает `buildEffect` энергии; boost и остаток работ делают простой пересчёт ненадёжным без дополнительных данных. Конец строительства удаляет construction site, поэтому сохранять его id и привязку до действия. В доступных константах engine нет `EVENT_SPAWN`: стоимость тела, имя creep, состояние spawn и изменения запасов дают косвенные свидетельства, но не отдельное событие расхода. Даже при наблюдении всех участников не приписывать одну и ту же дельту нескольким операциям; неоднозначные случаи остаются UNKNOWN. Исходники: [build](https://github.com/screeps/engine/blob/master/src/processor/intents/creeps/build.js), [transfer](https://github.com/screeps/engine/blob/master/src/processor/intents/creeps/transfer.js), [withdraw](https://github.com/screeps/engine/blob/master/src/processor/intents/creeps/withdraw.js), [constants](https://github.com/screeps/common/blob/master/lib/constants.js).

## Модули и поставка

Screeps использует собственный CommonJS-подобный загрузчик. В локальном engine `game/game.js` `requireFn` только удаляет начальное `./` и ищет получившееся имя в карте модулей: Node-подобное разрешение относительно директории вызывающего файла не доказано. Поэтому локально работающий `require('./x')` из вложенного файла нельзя без проверки считать переносимым. Сборка должна явно сопоставлять имена и переписывать imports либо выдавать один bundle с `main` и `module.exports.loop`; проверять именно загружаемый артефакт на целевом runtime, включая циклы зависимостей и отсутствующие модули. Локальный loader обнаруживает циклический require как ошибку. Исходник: [game.js](https://github.com/screeps/engine/blob/master/src/game/game.js).

До реализации необходимы изолированные проверки целевого driver: обычное исключение, исчерпание CPU и сериализация Memory до/после выдачи intents; конкурентные spawn/build/transfer, потеря видимости и перезапуск; загрузка собранных модулей. Результаты нельзя распространять на иной runtime без проверки.
